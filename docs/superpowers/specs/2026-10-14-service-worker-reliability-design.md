# Надёжная загрузка Finora в Chrome и Safari

## Цель

Исключить ошибку Safari `FetchEvent.respondWith received an error: Returned response is null` и обеспечить предсказуемое поведение Finora при доступной и недоступной сети.

Исправление касается только Service Worker и проверок его поведения. DNS-доступность домена `pages.dev` зависит от сети пользователя и не может быть исправлена кодом приложения.

## Подтверждённая причина

Текущий `sw.js` перехватывает почти все запросы и выполняет:

```js
fetch(request).catch(() => caches.match(request))
```

Если сеть недоступна и запрошенного ресурса нет в Cache Storage, `caches.match()` возвращает `undefined`. `FetchEvent.respondWith()` обязан получить `Response` или promise с `Response`; Safari отклоняет пустой результат и показывает ошибку `WebKitServiceWorker:0`.

Отдельная сетевая проверка показала, что Safari без сохранённого Service Worker не разрешает `finora-1m8.pages.dev`. Поэтому исправление Service Worker должно убрать ложную внутреннюю ошибку WebKit, но не обещает обход DNS-блокировки.

## Рассмотренные подходы

### 1. Network-first с гарантированным fallback — выбран

- Сначала запрашивать ресурс из сети.
- При сетевой ошибке возвращать точное совпадение из кэша.
- Для навигации возвращать закэшированный `index.html`.
- Если fallback отсутствует, возвращать явный `503 Response`, а не пустое значение.
- Не перехватывать запросы с методом, отличным от `GET`.
- Не перехватывать Supabase и внешние CDN-запросы.

Плюсы: минимальное изменение, сохраняет текущую архитектуру и устраняет конкретный дефект Safari.

### 2. Полностью удалить Service Worker

Плюсы: браузер всегда показывает исходную сетевую ошибку. Минусы: исчезает PWA-кэширование, а ранее установленные Service Worker всё равно нужно корректно деактивировать. Не выбран.

### 3. Cache-first для всех локальных ресурсов

Плюсы: сильная офлайн-поддержка. Минусы: повышается риск показа устаревшей версии финансового приложения и усложняется обновление. Для текущей задачи избыточно. Не выбран.

## Проект решения

### Кэширование

- Повысить имя кэша с `finora-v1` до `finora-v2`, чтобы браузеры активировали новую версию.
- На установке кэшировать `./index.html`.
- На активации удалять кэши Finora старых версий, не затрагивая чужие кэши origin.

### Обработка запросов

1. Пропускать не-`GET` запросы без вызова `respondWith()`.
2. Пропускать Supabase и внешние CDN-запросы напрямую в браузер.
3. Для остальных запросов использовать network-first.
4. При сетевой ошибке:
   - вернуть совпавший ресурс из кэша;
   - для навигационного запроса попробовать `./index.html`;
   - если ответа нет, вернуть явный текстовый `503 Response`.

При любых обстоятельствах обработанный запрос должен завершаться объектом `Response`.

## Проверки

До изменения создаётся автоматический тест, который исполняет `sw.js` в изолированном контексте с подменяемыми `fetch` и Cache Storage.

Обязательные сценарии:

1. Успешный сетевой запрос возвращает сетевой `Response`.
2. Сбой сети и найденный кэш возвращают закэшированный `Response`.
3. Сбой сети, отсутствие точного ресурса и навигация возвращают `index.html`.
4. Сбой сети и полное отсутствие кэша возвращают `503 Response`, а не `undefined`.
5. Не-`GET`, Supabase и CDN-запросы не перехватываются.
6. Активация удаляет только устаревшие кэши Finora.

После автоматических тестов сайт запускается локально по HTTP и проверяется в Chrome и Safari. В браузерах отдельно проверяются первая загрузка, повторная загрузка после установки Service Worker и режим недоступной сети.

## Границы изменения

- Не изменять бизнес-логику `index.html`.
- Не менять Supabase, данные пользователей, аутентификацию или схему БД.
- Не менять Cloudflare Pages до успешной локальной проверки.
- Не объединять `dev` с `main` и не публиковать без отдельного подтверждения пользователя.

## Критерии приёмки

- Автоматические проверки проходят без ошибок.
- `respondWith()` никогда не получает `undefined` для перехваченного запроса.
- При доступной сети Finora загружается как раньше.
- При недоступной сети Safari не показывает `Returned response is null`.
- Рабочие изменения ограничены `sw.js` и файлами тестов/документации.
