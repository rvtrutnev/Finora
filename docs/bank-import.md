# Импорт банковских выписок

Откройте вкладку «Импорт», выберите файл, дождитесь чтения и проверьте строки перед сохранением в бюджет. Чтение файла не создаёт операции. Импорт добавляет доходы и расходы бюджета; баланс кошелька не пересчитывается.

## Поддерживаемые форматы

| Банк | Проверенный PDF-шаблон | Особенности |
| --- | --- | --- |
| Т-Банк | Дата и время операции, дата списания, сумма в валюте операции, сумма операции в валюте карты, описание, номер карты | Используется сумма в валюте карты. |
| Альфа-Банк | Дата проводки, код операции, описание, сумма в валюте счёта | Дата покупки и MCC берутся из описания при наличии, иначе используется дата проводки. Неподтверждённые суммы показываются отдельным предупреждением. |
| ВТБ | Дата и время операции, дата обработки банком, сумма операции, приход/расход по счёту/карте, описание, получатель/отправитель | Направление и сумма определяются по колонкам прихода и расхода по счёту; поддерживаются многострочные ячейки. |
| ОТП | Номер, дата операции, операция, расход, приход, назначение платежа | Альбомная таблица, включая продолжение без заголовка. Валюта берётся из явного обозначения счёта над таблицей («Валюта счета: USD», «Счет: … (руб.)»). Отсутствующая или противоречивая валюта отклоняется с пояснением; RUB автоматически не подставляется. |

Поддерживаются конкретные структуры таблиц, а не все документы этих банков. Переставленные колонки, поворот страниц, новая вёрстка и другой тип отчёта могут потребовать отдельного адаптера. Банк определяется по полному заголовку и положению колонок первой страницы.

Ограничения PDF: до 50 МиБ, 200 страниц и 1 000 000 текстовых элементов. Нужен текстовый PDF. Сканы без текстового слоя, документы с паролем, повреждённые и неизвестные форматы отклоняются с сообщением; OCR не выполняется. Частичный разбор сопровождается предупреждениями. Сопоставьте число строк, суммы, валюту и даты с выпиской; предпросмотр сам по себе не подтверждает полноту.

CSV, XLS и XLSX остаются доступны для шаблонов Т-Банка и Альфа-Банка. CSV читается как UTF-8, при ошибке декодирования — Windows-1251; поддерживаются разделители, кавычки и переносы строк внутри полей. Из Excel читается первый лист через подключённый модуль XLSX. Нужны заголовок «Дата операции», описание и сумма; сумма/валюта платежа или счёта имеют приоритет перед исходной суммой/валютой операции. При отсутствии валюты используется RUB. Отменённые и отклонённые строки пропускаются. Ручной выбор банка доступен для таблиц, но не исправляет неизвестную структуру колонок. Экспорт всего Finora в CSV не является банковским шаблоном.

## Проверка и сохранение

Для CSV Т-Банка с колонкой статуса допускаются только подтверждённые статусы `OK`, «Выполнен», «Выполнена», «Выполнено». Отменённые, ожидающие обработки, неизвестные и пустые статусы исключаются с предупреждением о каждой строке. Таблицы без колонки статуса сохраняют прежнее поведение.

Черновики категории, подкатегории, условия правила и текста/MCC сохраняются при ошибке и обновлении предпросмотра. Успешное сохранение закрывает соответствующую форму; отмена, новый файл и смена аккаунта очищают черновики.

Для каждой выбранной строки нужна категория. Предлагаются только существующие категории и подкатегории соответствующего типа: сначала по пользовательскому правилу описания, затем по MCC, затем по известным соответствиям. Первая категория списка не используется как запасная. Категорию или подкатегорию можно создать прямо в импорте; правило описания или MCC — сохранить отдельным действием.

Переводы, наличные, возвраты и строки с другими предупреждениями первоначально не выбраны. Проверьте их смысл для бюджета и включите нужные строки вручную. Переключение доход/расход очищает категорию. Доходы можно исключить переключателем.

Повтор того же файла использует SHA-256 файла и ключ строки: сохранённые операции повторно не создаются. Одинаковые покупки внутри файла сохраняют кратность. Совпадение даты, типа, валюты, суммы и описания в другом файле считается возможным дублем и требует подтверждения; оно не доказывает совпадение банковского счёта. После частичного сбоя повторите сохранение оставшихся строк; успешные строки отмечаются отдельно. Смена аккаунта очищает предпросмотр и отменяет применение отложенных результатов старого аккаунта.

## Конфиденциальность

PDF разбирается в браузере закреплённой локальной копией PDF.js из `vendor/pdfjs`; исходный файл не загружается в сервис распознавания и не сохраняется в базе. Библиотека и worker загружаются с того же сайта. PDF-скрипты, eval, вложения и внешние шрифты обработчиком не используются. Приложение и существующие CDN-зависимости требуют обычной загрузки ресурсов сайта; полная автономность приложения не обещается.

При сохранении в Supabase передаются выбранные нормализованные операции, категории, правила, хеш файла и ключи импорта. Правила сохраняются отдельным действием. Описания проходят маскирование распознаваемых номеров карт, счетов и телефонов, но это эвристика: имена, назначения платежей и оставшиеся сведения нужно проверить самостоятельно. Хеш и ключи не являются шифрованием или гарантией анонимности. Не добавляйте оригинальные выписки, частные описания, скриншоты или диагностические выгрузки в репозиторий.

## Ручное развёртывание

1. Выполнить проверки ниже и браузерную приёмку на синтетических данных для Classic/Pixel и мобильного/настольного размера.
2. В тестовом окружении проверить существующие `auth.users`, `public.categories`, `public.budget_items`, их схему и политики владельца. Синтетическая SQL-фикстура не заменяет проверку реальной схемы. Подготовить резервную копию по процедуре проекта.
3. Уполномоченному администратору вручную применить `supabase/migrations/202610200002_bank_import.sql`: таблицы `bank_import_rules`, `bank_import_keys`, политики RLS, RPC `finora_import_add_category`, `finora_import_operation`. Повторное применение поддерживается; приложение миграцию не запускает.
4. Двумя тестовыми пользователями проверить изоляцию правил/ключей/операций, отказ анонимному пользователю, создание категорий без потери существующих, повтор файла, две одинаковые покупки, подтверждение совпадения и атомарный откат при сбое. Отдельно проверить реальный Supabase API и настройки доступа тестового окружения.
5. После отдельного разрешения на публикацию согласованно выложить `index.html`, `js/import-core.js`, `js/import-pdf.js`, `js/import-ui.js`, `sw.js`, `vendor/pdfjs/` и остальные ресурсы релиза. Проверить доступность PDF.js/worker, обновление service worker и отсутствие старых модулей в кеше. Производственную миграцию и сохранение выполнять по отдельному разрешению: локальная приёмка их не подтверждает.

В рамках текущей разработки публикация, push и производственная миграция не выполнялись. Для отката клиента используйте предыдущий согласованный релиз; удаление таблиц/ключей требует отдельного решения, поскольку уничтожает историю повторного импорта.

## Воспроизводимые проверки

```sh
node --test tests/*.test.mjs
node --check js/import-core.js
node --check js/import-pdf.js
node --check js/import-ui.js
node --check sw.js
git diff --check
```

Необязательный SQL-тест требует отдельно установленного `@electric-sql/pglite`, создаёт временную базу в памяти и не подключается к Supabase:

```sh
FINORA_PGLITE_MODULE=/absolute/path/to/pglite/dist/index.js node tests/bank-import-sql.mjs
```

Он применяет `tests/fixtures/bank-import-schema.sql`, дважды выполняет миграцию и проверяет повтор сохранения, кратность одинаковых покупок, подтверждение совпадения, валидацию, откат транзакции, слияние категорий, RLS разных владельцев и отказ анонимному пользователю. PGlite проверяет SQL локально; это не проверка работающего Supabase, его REST/RPC-слоя или производственных данных.
